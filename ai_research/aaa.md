# 格式转换诀窍

1. 引用标记的清理

原始文件中的 cite 标记使用了 Unicode 私有区字符 U+E200/U+E202/U+E201 作为分隔符，在标准 Markdown 渲染器里会显示为乱码或方框。

先用 xxd 做 hex dump 查看原始字节，确认具体编码后再写正则。确认 EE 88 80 = U+E200, EE 88 82 = U+E202, EE 88 81 = U+E201 之后，perl 正则可以精确写成：

s/\x{E200}cite.*?\x{E201}//g

.*? 非贪婪匹配确保不会把同一行里的两个引用合并吃掉。

2. 数学公式分隔符转换

(...) 和 [...] 是 Pandoc 方言，GitHub/GitLab/VS Code/Obsidian 的 MathJax/KaTeX 渲染器只认 $...$ 和 $$...$$。

转换顺序很重要：先转展示公式，再转行内公式。因为 ] 中包含 )，若先执行行内转换，s/)/$/g 会误匹配展示公式的后半截。LaTeX 命令在原始文件中已是单反斜杠，不需要再做 \\ -> \\ 归约。

3. 善用 hex dump 而不是猜

遇到看起来像乱码的字符时，不要根据终端渲染结果猜，直接用 xxd 看原始字节。终端和 IDE 对不同 Unicode 私有区的渲染行为不一致，肉眼看到的往往不是真实的。

4. 一句话总结

hex 确认字节 -> perl 精确正则 -> 先展示公式再行内 -> 顺手清多余空格。
